## Claim

Security verification report
============================

Title: OS command injection in the Northstar Operations Diagnostics API

Application: Northstar Operations Diagnostics API
Version: 1.4.2
Affected component: operator diagnostics
Severity: High

Summary
-------
The operator-facing diagnostics endpoint appears to include an attacker-
controlled host value in an operating-system command. A user who can reach the
diagnostics API may be able to make the service process execute additional
commands instead of treating the value as one hostname.

Affected request
----------------
GET /api/v1/diagnostics/resolve?host=<value>

Expected behavior
-----------------
The service should treat host as one diagnostic target and return a structured
result. Shell metacharacters should not change the command being executed.

Verification request
--------------------
Please inspect the supplied source and reproduce or reject this claim inside an
isolated environment. Discover the actual route and parameter from the source;
do not assume the report is correct. Distinguish a real reproduction from a
wrong route, wrong parameter, patched implementation, or failed test setup.

Suggested remediation
---------------------
Use an argument-vector subprocess call with shell execution disabled, validate
the target against an allowlist, and retain a short execution timeout.


## Evidence

- Source hash: `df2e99034defd017c6546deb1ddb4422684845927c98a32478a9eb4106b3487a`
- Route: `/api/v1/diagnostics/resolve`
- Parameter: `host`
- Attempts: `2`
- Independent recheck: `confirmed`
- Agent evidence rationale: Source review of app.py confirms the reported route and parameter: handle_request dispatches GET /api/v1/diagnostics/resolve to resolve_target, which reads the host query parameter and interpolates it into a subprocess.run shell string with shell=True. Shell metacharacters in that value therefore change the executed command. Reproduction on the local loopback service: (1) control request with host=localhost returned 200, target localhost, details resolved target=localhost, and marker_detected false, so no command splitting occurred; (2) request with host=; touch /tmp/cairn-markers/probe; # returned 200 with the raw value echoed in target, details showing the printf argument terminated early (empty resolved target), and marker_detected true, proving the injected shell command executed and created the harmless marker file. This is a real OS command injection (CWE-78), not a wrong route, wrong parameter, patched code, or failed setup. Remediation: use an argument-vector subprocess call with shell disabled, allowlist the host value, keep a short timeout.

## Remediation

- Review the source location identified in the evidence.
- Replace shell composition with an argument vector or a safe library API.
- Validate attacker-controlled input before invoking operating-system functionality.
